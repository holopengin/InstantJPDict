# InstantJPDict 1.0.0-rc13 — tester notes

## Fixed

- **Non-BMP alternatives no longer crash recognition.** The unified page
  pipeline crossed a model class such as `U+1F468` (128104) as a raw Unicode
  scalar. Kotlin's `Char(Int)` only accepts UTF-16 code units, so the first
  line with that class in its top-15 table threw
  `Invalid Char code: 128104`. The page shim now uses the same UTF-16 mapping
  the pre-unified decoder used; text is unchanged and the alternative list
  stays aligned.
- Includes rc12's `libomp.so` linkage fix (the rc11 native library could not
  dlopen on the first Rust call).

## Changed

- A capture still crosses into `jpdict_core::page_ocr` once and comes back
  with every line: text, alternatives, raw CTC rows, char columns and char
  boxes. Detection, recognition, kana correction and CAP placement run in
  that call. Cancellation reaches detection, job dispatch and long-line
  chunking.

## Known

The `recognition-01-tategaki-fonts` "た的めしがき" text drift is pre-existing
and unchanged; it is not a regression in this release.
