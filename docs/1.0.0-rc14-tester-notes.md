# InstantJPDict 1.0.0-rc14 — tester notes

This release removes the Kotlin OCR backend. All detection, recognition,
stitching, CTC decode, kana correction and char-box placement now run in the
Rust page call.

## Changed

- **One backend.** The old Kotlin `OcrEngine` detection/recognition/stitch
  sections, `DetNcnn`, `RecNcnn`, `KanaSizeNcnn`, the JNI shell and the CMake
  build are gone. `OcrEngine` is now the page-call facade plus the model-free
  re-decode/geometry helpers.
- **Smaller APK.** `libncnn_jni.so` is no longer packaged; ncnn is linked into
  `libnav_graph_core.so`. The APK drops from ~51 MB to ~44 MB.
- **Faster page detection.** The page path now uses the shared C++ integer-pad
  letterbox (`det_build_input`) instead of a Rust letterbox image and a second
  normalization pass. On the Pixel 7a that cut the detection stage from
  ~315–341 ms to ~278–319 ms.
- **No Kotlin kana/encoder mirrors.** Kana correction and its window encoder
  are the Rust implementations; the conformance suite calls the Rust encoder
  and policy directly. The obsolete debug-screen kana-epsilon slider and
  verbose-OCR switch are removed with the JNI backend.
- **Char-placement facade slimmed.** Rust now reduces the crop's ink evidence;
  the Kotlin copy of the mask/profile reduction is gone, and the placement
  defaults come from Rust instead of 27 Kotlin literals.

## Profile snapshot

Warm, interleaved runs on a Pixel 7a, same 1080×2400 tategaki page:

- New page call: ~764 ms median before the letterbox change, ~768 ms after;
  detection ~303–315 ms before, ~278 ms after.
- Old mixed Kotlin/Rust path: ~1002–1034 ms median on the same page.
- Your reported page: old ~670 ms, new ~748 ms — the remaining gap is the
  Rust image resize/Skia difference in detection; recognition is already
  faster in Rust.

## Known

The `recognition-01-tategaki-fonts` "た的めしがき" text drift is pre-existing.
The debug screen no longer has the per-call verbose native-log switch because
the JNI kernel it gated is gone.
