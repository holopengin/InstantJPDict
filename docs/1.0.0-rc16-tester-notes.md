# InstantJPDict 1.0.0-rc16 — tester notes

Detector filter correction on the all-Rust page path.

## Changed

- **The page detector now uses Skia-style plain bilinear**, matching
  `Bitmap.createScaledBitmap(..., filter=true)` from the old Android detector.
  The previous rc15 page path used a box/area filter, which the phone never
  used.
- Pulls `jpdict-core` `dd50c97` (PC master): `fast_image_resize`
  `Interpolation(Bilinear)` for the page detector input, and
  `PageOcrOptions::default` now selects the shared C++ letterbox so a binding
  starting from defaults cannot silently take the desktop float-offset path.
- Desktop/PC preprocessing is unchanged.

## Validation against the old JNI detector

On the Pixel 7a, `ebook_tategaki.png` (1080×2400), old rc13 JNI detector vs
the new `dd50c97` page detector:

- old boxes: **18**
- new boxes: **18**
- nearest-centre delta: **mean 1.52 px**, **max 3.0 px**
- 14 of 18 matched boxes are exactly **1.0 px** apart, almost all a one-pixel
  x shift; the rest differ by 2–3 px because a box edge/height moved by 1–2 px.
- no box is missing, added, or structurally reordered.

That is close enough to keep `fast_image_resize` Bilinear rather than the
hand-written plain-bilinear fallback.
