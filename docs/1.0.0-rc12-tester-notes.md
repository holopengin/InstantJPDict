# InstantJPDict 1.0.0-rc12 — tester notes

This release moves the whole OCR page into one Rust call.

## Changed

- **One page in, one page out.** A capture now crosses into
  `jpdict_core::page_ocr` once and comes back with every line: text,
  per-character alternatives, raw CTC rows, char columns and char boxes.
  Detection, recognition, kana small/large correction and CAP placement all
  run in that call. The old Kotlin `detectLines` + `recognizeStreaming` pair is
  no longer used by the overlay.
- **Cancellation reaches the native work.** Closing the overlay (or otherwise
  cancelling the capture coroutine) sets a Rust flag. Detection checks between
  component rows and around the ncnn call; recognition checks before each line
  and inside long-line chunk loops.
- **The recognition fast paths stay in Rust**: native top-K packing, the
  lengthwise squish, portrait 270° handling, long-line chunk/stitch, worker
  fanout and the compact `TimestepTopK` table (rebuilt from the flattened rows,
  so rows stay lazy).
- **The debug switches still apply per run**: detection size/threshold/unclip,
  furigana, rotated detection, CAP/snap/uniform, squash and worker count cross
  in the page options, so changing one does not rebuild the engine.
- Includes the line-ending closing-mark fix and the CTC space-run collapse
  already on `master`.

## Known

The `recognition-01-tategaki-fonts` "た的めしがき" text drift is pre-existing
and unchanged; it is not a regression in this release.

## Update
