# InstantJPDict 1.0.0-rc15 — tester notes

Performance pass on the all-Rust page pipeline.

## Changed

- **Detection resize:** the detector content is now resized with the SIMD
  `fast_image_resize` (box for downscale, bilinear for upscale) and packed
  straight to ARGB, then handed to the shared C++ integer-pad letterbox. On
  the Pixel 7a, detection dropped from ~278–319 ms to **~241–246 ms**.
- **Raw CTC table:** the per-timestep alternatives cross as packed primitive
  arrays (UTF-16 units + f32 scores + row boundaries) instead of one `GapCell`
  object and one boxed score per cell. Kotlin rebuilds the compact
  `TimestepTopK` from those arrays.
- **Pixel upload:** `copyPixelsToBuffer` replaces the Kotlin ARGB→RGBA
  per-pixel loop. The byte order is pinned by a device test (RGBA on the Pixel
  7a); preparation is ~6–8 ms.
- Includes rc14's removal of the Kotlin backend: no `libncnn_jni.so`, ~44 MB
  APK, one Rust page call.

## Measured

Pixel 7a, warm 1080×2400 tategaki page, new page call:

- detect **~243 ms**
- recognition **~560–630 ms**
- prepare **~7 ms**
- total **~870–940 ms**

The recognition number includes the extra small lines the new detector finds;
detection itself is now faster than the old Kotlin detector (~264 ms).

## Known

Detection box sets may differ slightly from the old Kotlin/Skia detector
because the resize filter differs; the content lines still recognize. The
`recognition-01-tategaki-fonts` text drift remains pre-existing.
