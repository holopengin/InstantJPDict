Modification: static Regular instance
-------------------------------------

The variable font cannot ship as-is — its default instance is Thin, which would
render a hairline face — and shipping the variable font would put 9.6 MB per
face into the APK. The bundled file is a static instance at wght=400 produced
with fontTools:

  fontTools.varLib.instancer.instantiateVariableFont(font, {"wght": 400},
      updateFontNames=True)

That is the only modification: the outlines are the variable font's Regular
master, the fvar/gvar/HVAR/avar tables are dropped, and the name table says
"Noto Sans JP / Regular". The result is distributed under the same OFL-1.1. The
Reserved Font Name 'Source' is not used by the derivative (its name is
"Noto Sans JP", which is not the reserved name).

Vertical substitution verified (issue #47)
------------------------------------------

The overlay renders vertical lines with Paint.fontFeatureSettings = "'vert' 1",
so the face must carry the vertical GSUB features. Checked with fontTools on the
committed file:

  vert  : lookups 16/17/18, single substitutions covering 378 + 1 + 4 glyphs
          (、→uniFE11, 。→uniFE12, 「→uniFE41, 」→uniFE42, （→uniFE35,
            ）→uniFE36, ー→glyph17789)
  vrt2  : lookup 16, covering the same 378 glyphs
  scripts: both registered under DFLT, cyrl, grek, hani, kana and latn
          (default and JAN langsys); vhea/vmtx vertical metrics present.

The JVM test OverlayFontTest parses this committed file and fails if vert or
vrt2 disappears, so a future font swap cannot silently drop the substitution.
